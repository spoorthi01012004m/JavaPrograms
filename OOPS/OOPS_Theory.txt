===================================== Encapsulation ========================================
- Wrapping variables (data) + methods

While writing a class it should achieve encapsulation otherwise it wil become loose code.
Lets assume we have created a class with public data and some public method to modify the data but when another class using this class it can directly modify the data without implementing method 
so, this is not a proper way to modify the data , it should be modified through methods
Encapsulation says that nobody can change your data directly. Main purpose of encapsulation is to hide sensitive data or details while allowing the controlled access 

To achieve encapsulation follow below rules :
* Keep class data as private
* Keep methods public to modify data through it 


====================================== Inheritance ==========================================
Inheritance is a key concept in OOPs where inheritance allows a class to use properties and methods of an another class.

Functionalities developed by parents class can be reused by child class.

           |-----IS-A relation
child ---->extends -----> parent
ex :
class parent{
}
class child extends parent{   // child have a properties of parent 
}
where child class can access all the attributes other than private and all the methods.

what is the purpose of inheritance ?
-- Inheritance allows to use the existing class instead of writing logics and everything from the scratch while creating new class 

why do we need inheritance ?
-- code reusability this avoids code duplication and makes program more effiecient and easy maintainable , reduces time.
-- Method overriding - with the help of inheritance we can modify or extend the functionality of the parent class in th child class.

Terms used inheritance:
* super class (parent)
* sub class (child)

-Disadvantage of inheritance:
* Heavy loading of all the parent class
* Tight couple 

Type of Inheritance:
1. single  - one parent , one child 
2. multilevel - one parent , more than one level child
3. hierarchical - one class parent , more than one child class inherit parent properties
4. multiple  - more than one parent , one child class  ----> This creates ambiguity so, it doesn't works in java (this problem is called Daimond problem or DOD).
5. Hybrid - mixture of all other types

##Diamond problem or DOD problem --> Arises because of multiple inheritance ambiguity

Up casting and Down casting
---------------------------

Assume 
class A(parent){

 //parent class method 
  public void printFun(){
   system.out.println("A.printFun().....parent");
   }
} 
class B(child) extends A(parent){

  //parent class method is overridden 
  @Override
  public void printFun(){
  system.out.println("B.printFun()......Child");
  }
}

public class Driver{
 public static void main(String args[]){
  // new B(); //this also legal way to call object 
  A obj1 = new B(); // calling child class object using parent class reference 
                    // This is auto up casting 
					
  B obj2 = new B();
  
  obj1.printFun();
  B obj3 = new A(); // This is not possible in java , creates ClassCastException 
  B obj4 = (B)obj1; // in this way down casting can be done in java 
  obj4.printFun();  //calling overridden method of an object
      }
  }
 
 
Main points to remeber :
* Compile time : When we try to creat object first it checks is there any with that name in the class if that method does not present in that class it shows compilation error.
* Runtime : When the object created after compilation it looks for particular object method then executes.

=============================================Interface===========================================================
- Interface tells what need to be done , it depends on the classes , how it is getting implemented.
- It will not have any logic, but if any class implementing this interface then it should implement all the methods of interface it is like an agreement.
- Interface have only abstract.
  
 In java version 1.7 or 7 version or before interface by default it consider all the methods as public abstract even if we don't mention it.
 
problem with java 7 0r before:
If anything added after years or new feature came then it would impact on all the classes which implements interface.
Assume some features added after some years in TicketBooking then it was forcing all the classes which are implementing it.
--drawback is even if class do not need that feature implement forces that to implement all the methods.


To overcome this in java 8 version 'default' key word is introduced 
-by mentioning default in method that method will become optional body need to be implements
 ex -- public default void addUpgrade(){
        }
		
		Backward Compatibility  - if we are adding new feature that should not disturb the existing feature
       ------------------------

- One more feature added in java 8 :
  Assume all child classes required to use print() method with same logic but again it will take time if we write this methods in every class.
  So, to avoid this in java 8 static method is introduced - this static method is included in interface with complete body, 
  it can act as common method or utility method to all child classes.
